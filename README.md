## ✏️ Rules

- **매주 도전 문제 2문제 풀이**
  - 🥈 **쉬운 도전 문제**: 실버 난이도
  - 🥇 **어려운 도전 문제**: 골드 이상 난이도
- **매주 주제 1개** 선정 (예: BFS, DP, 정렬 ...)
- **문제 선정**: haruzora1(수연), msik-j(민식)이 매주 주제에 맞는 도전 문제 2개를 선정합니다.
- **모임**: 매주 1회 모여 도전 문제 풀이를 공유합니다.
- **코드 리뷰**: PR에 서로 코드 리뷰를 남깁니다.

## ⚠️ 규칙 및 컨벤션

### 📁 폴더 구조

`본인닉네임/사이트/문제번호_문제제목.확장자` 형식을 지켜주세요.

```
yula2000/
├── BOJ/
│   ├── 1000_A+B.py
├── PGS/
│   ├── 42840_모의고사.py
```

### 💬 커밋 메시지

`{이모지}{태그}: [{사이트}] {문제번호} {문제제목}`
⚠️ 이모지는 필수 사항 아닙니다! ⚠️

- 예시: `✨feat: [BOJ] 8979 올림픽`


### 🔁 PR(Pull Request)

- **PR** (도전 문제 PR, 주 1회)

## 🔍 참여 방법

## 👓 초기 설정 (최초 1회)

1. 레포지토리를 clone합니다.

```bash
   git clone https://github.com/yula2000/Solve-or-Die-algorithm-study.git
   cd Solve-or-Die-algorithm-study
```

2. 현재 브랜치를 확인합니다. (`master`여야 해요)

```bash
   git branch
```

3. 본인 닉네임으로 브랜치를 생성하고 이동합니다.

```bash
   git checkout -b 본인닉네임
```

4. 본인 닉네임으로 폴더를 만들고 빈 파일을 추가합니다.

```bash
   mkdir 본인닉네임
   touch 본인닉네임/.gitkeep
```

5. add, commit, push합니다.

```bash
   git add .
   git commit -m "📝docs: add 본인닉네임 folder"
   git push origin 본인닉네임
```

> 💡 `ls 본인닉네임` 쳤을 때 아무것도 안 나와도 정상이에요! `.gitkeep`은 숨김 파일이라 그래요.

&nbsp;

### 👓 문제 풀고 PR 올리기

1. 내 폴더 안에 `BOJ`, `PGS` 등 사이트별 폴더를 만들고 코드를 작성합니다.

2. 변경 사항을 저장(add)하고 커밋(commit)합니다.

   ```bash
   git add .
   git commit -m "✨feat: [BOJ] 8979 올림픽"
   ```

3. 본인 브랜치로 push합니다.

   ```bash
   git push origin 본인닉네임
   ```

4. GitHub에서 `Pull requests` 탭 → `New pull request` 클릭

5. 브랜치 방향을 확인합니다.
   - **base**: `master` ← **compare**: `본인닉네임`

6. **✅ [PR 규칙](#-prpull-request)에 맞게 제목과 내용을 작성**하고 `Create Pull Request`를 누릅니다.

7. 다른 멤버들의 PR에도 코드 리뷰를 남겨주세요 💬

&nbsp;

### 🔄 master 최신화하기 (동기화)

다른 멤버의 PR이 merge되면 `master`가 업데이트됩니다. 주기적으로 내 브랜치에도 최신 내용을 반영해주세요.

```bash
# 1. master 브랜치로 이동
git checkout master

# 2. 원격 저장소의 최신 master를 가져옴
git pull origin master

# 3. 다시 내 브랜치로 이동
git checkout 본인닉네임

# 4. master의 변경사항을 내 브랜치에 반영
git merge master
```

&nbsp;

### 🔄 GitHub 웹에서 master 최신화하기 (동기화)

다른 멤버의 PR이 merge되면 `master`가 업데이트됩니다. 주기적으로 내 브랜치에도 최신 내용을 반영해주세요.

**방법 1. GitHub 웹에서 (간단)**

1. GitHub 레포에서 본인 브랜치로 이동
2. `Sync branch` 버튼 클릭

**방법 2. 터미널에서**

```bash
# 1. master 브랜치로 이동
git checkout master

# 2. 원격 저장소의 최신 master를 가져옴
git pull origin master

# 3. 다시 내 브랜치로 이동
git checkout 본인닉네임

# 4. master의 변경사항을 내 브랜치에 반영
git merge master
```

&nbsp;

### ⚡ 충돌(Conflict)이 났을 때

같은 파일을 여러 명이 수정했을 때 충돌이 발생할 수 있습니다. 폴더 구조를 **본인 닉네임 폴더 안에서만** 작업하면 충돌이 거의 발생하지 않습니다.

만약 충돌이 발생했다면:

```bash
# 충돌난 파일을 직접 열어서 수정 후
git add .
git commit -m "♻️refactor: resolve conflict"
```
